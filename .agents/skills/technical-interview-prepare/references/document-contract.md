# Interview prep document contract

默认中文归纳，保留问题原名及有用的英文问法。canonical prep 放准备题单、进度和本轮说明；
完整面经与题目证据账必须独立成文件。两者分别回答“准备什么”和“依据是什么”，不复制来源库存。

## 位置与身份

输出在 `../career-docs/context/Interview/<company>/`（相对于 `job-discovery/` 仓库根目录；
非同级布局使用已解析的 Career Docs 根目录）。
已有同一职位与已约轮次的 canonical prep doc 则原地更新研究部分，保留勾选进度及其他个人内容。
新文件用 `<company>-<role>-interview-prep-<scheduled-or-research-date>.md`。
同目录的证据文件沿用同一命名主干，将 `interview-prep` 换成 `interview-evidence`；已有对应
证据账则复用。prep 顶部链接证据账，证据账顶部链接回 prep，并记录同一职位/轮次及采集截止。
本规范第 1–3 节属于 prep，第 4–5 节属于证据文件；prep 只保留覆盖状态及影响准备的简短待确认项。
拆分旧文档时完整迁移来源及历史覆盖记录，保留 Q-ID/S-ID、顺序、进度和内容；更新所有受影响
链接为 prep `#^q...` ↔ 证据文件 `#^s-...` 的跨文件块引用，不改冻结原件。
同一已约 loop 可含多轮；不同职位或不相关轮次不合并。公司首页/索引只在需要时加一个链接。

标题 `# <Company> <Role> — Interview Prep`。顶部记录：核验时间与时区、role/level/team、
requisition/tracker identity、已约范围、准确面试时间或 deadline、身份来源文件。

### Obsidian 格式

通用语法复用已安装的 `obsidian-markdown` Skill；本节保留面试题单的专用约定。
已有 prep 的结构、进度与个人内容优先保留，按实际需要使用属性、callout或嵌入。

- 先确认目标 vault 根目录；当前 Career Docs vault 为 `career-docs/context/`（含 `.obsidian/`）。
  库内文档用从 vault 根开始的显式路径，如 `[[Interview/oracle/文件名|显示文字]]`，省略 `.md`；
  图片/PDF 等附件保留扩展名。不要把 `/Users/...` 绝对路径当库内链接，以免打开或新建错误笔记。
- 题目和来源用稳定块 ID：任务首行末尾放 `^q001`，来源标识段末尾放 `^s-w1-001`；引用用
  `[[Interview/oracle/证据文件#^s-w1-001|S-W1-001]]` 与 `[[Interview/oracle/prep文件#^q001|Q001]]`。
  同页标题链接用 `[[#Coding]]` 等实际标题，不依赖 HTML `<a id="...">` 或 GitHub 标题 slug。
- 表格内 Wikilink 的别名分隔符转义为 `\|`。Obsidian 不支持定位表格单行；需逐项引用的
  归并/摘要索引用普通列表并附块 ID，不用复选框。正文详情用 Markdown，避免整段 HTML 包裹。
- 外部网页继续用 `[文字](https://...)`；库外文件及需外部工具打开的 JSON/TXT 原始日志用
  URL 编码的 `file:///...` Markdown 链接。行号/图片页码放在链接旁，不把 Codex 的 `:123`
  行号后缀写入文件目标。原始证据不为兼容渲染改写或复制。
- 修订后离线检查实际文件、块 ID、标题和双向链接即可，无需打开 Obsidian 验证。
  [官方链接语法](https://help.obsidian.md/links)及
  [表格转义规则](https://help.obsidian.md/advanced-syntax)为格式依据。

## 1. 每轮怎么面

| 轮次 ID / 已约时间与时区 | 形式与依据等级 | 时长 / 面试官 / 平台 | 考查内容与规则 | 直接证据 | 待确认 / 冲突 |
|---|---|---|---|---|---|

每轮分别写清 OA、live coding、pair programming、debugging、code review、system design、
OOD、BQ、HM/project deep dive、recruiter、presentation、take-home 或混合形式及顺序。
将事实细分，不要用一个“已确认”覆盖整行：如轮次名已确认，coding/OOD 比例仍可能未知。
注明允许语言、工具/AI、测试/运行环境和评估信号，未披露的字段明确标注。

- **已确认**：用户 明确说明或本轮邀请/recruiter/附件的直接证据；逐项引用。
- **推断**：同职位/级别/团队/地区/阶段的具体报告或公司指南支持；写推理和匹配边界。
- **未确认**：只有轮次名字、相关性不足、证据冲突未解或没有来源。不可用通常流程补成事实。

本轮证据与较新通用指南冲突时并列来源，标待确认，不默默替换邀请要求。

## 2. 应准备哪些题（含近期与高频）

这是唯一的准备/频次汇总区，依次设 **Coding、System Design、BQ** 三类原生 Markdown 任务列表。
每题标适用 R-ID，可对应多个已约轮次，不按 R-ID 再拆列表或重复列同题。仅请求单类时只产出
该类；完整调研中某类没有证据时注明“未找到本轮报告”，不凭空补题。

- Coding 包含算法、实现、debugging、code review、pair programming 等实际代码任务；
  System Design 包含系统/架构设计与 OOD。项目深挖按具体问法归类：架构与技术取舍归设计，
  ownership、协作、冲突、影响等经历问题归 BQ，保留原题型标签。确实不属三类的领域知识、
  presentation 等另列“其他题型”，同样按重要性排序，不为凑三类删题或改写问题性质。
- 每类先列本轮明确要求及可比真题，再在列表末尾列低匹配、营销/二手、仅题型或残缺线索，明确匹配
  边界。同级别 Screen/OA、轮次未知但岗位可比的亲历原题可进入主要比较范围，不能一律沉底。
  补充范围的高频不能挤到主要比较范围之前；低相关题仍保留。跨类型追问随主问题保留并标
  类型，不为分类拆掉现场追问关系；需要跨类引用时链接原 Q-ID，不复制任务或重复计数。

列表从上到下就是 用户 的准备顺序。每类实际顺序为“优先准备 → 接着准备 → 有余力再看”，
**同档内部也必须排序**。使用下面的先后关系，不用可相互抵消的主观加权分数：

1. **本轮明确要求优先**：只适用于邀请/recruiter 明确要求的具体准备内容，例如过往系统架构、
   失败经历及指定行为能力。泛称“考DSA”不授权把某道算法题升为本轮指定题；JD技术关键词、
   历史同团队问法也不能冒充当前指令。多个直接要求中，先覆盖不同的明确要求，再按下述证据
   顺序选择具体问法；不把同一能力的所有旧题都提升为最高档。
2. **确定可比范围**：同公司、相关工程职能且实际披露具体任务/问法的亲历原题进入主要比较。
   不因不同team就排除可比题。实习、明显异职能、纯营销/二手建议、仅题型及无法明确任务的
   残句保留为补充；来源类型不改变后文的完整库存与总提及计数。
3. **近期性优先**：主要比较范围按近90天 → 90天至6个月 → 更早的历史补充 → 日期未知排列。
   声明截止日及各档边界；这是准备时间档，不是命中概率。使用该题具体来源经历的面试日期；
   没有面试时间才以实际披露该题的发布日作替代，标“近期发布，面试时间未知”。更新/转载日
   不刷新旧面试。季度/月保留区间；跨档区间按其最早可能日期保守放档并注明跨档，不制造精确日期。
4. **同一时间档内比较级别和阶段**：同级别 Loop/onsite → 相邻级别可比 Loop → 同级别 Screen/OA
   → 级别或轮次未确认。Senior头衔、年资或“Round1”本身不证明级别或Loop；使用来源可证实的
   映射。同团队旧题不能跨时间档压过近期可比原题。
5. **证据确定性与独立重复**：同时间档、同级别/阶段档内，明确面试时间优先于仅有发布日期或
   跨档区间；再比较该时间档的同级别Loop独立经历数，以及其他可比独立经历数。历史累计次数
   只作后续参考，营销/转载不当成独立实考票。同作者/同经历跨站去重。
6. **最后打破接近条件下的并列**：同团队/相近技术方向 → 更近的有效日期 → 题意完整程度和
   能力覆盖。不能用“更经典”“更通用”、LC难度或算法topic把近期Loop原题降到旧题后。
   仍相当时保留原相对顺序，避免制造没有证据支持的精确名次。

日期、级别、轮次和题意必须来自同一条有效来源经历：不能借A来源今年Screen的日期和B来源
去年Loop的身份拼成“近期同级别Loop原题”。多来源题以最强的完整证据组合确定档位，其余
来源用于同档独立重复与背景支持；不直接取题目所有来源的最大日期或总提及数排序。

档位从证据导出：本轮明确要求及近90天可比原题为“优先准备”，其余6个月内可比原题为
“接着准备”，更早/日期未知及补充材料为“有余力再看”；不固定凑前10题或其他名额。
每题给一句可回查的排序理由，包含有效日期依据、级别/阶段及关键来源；不编造频次、分数或
命中概率。Q-ID固定且重排不改号；勾选状态用于记录进度，不改变证据名次。证据账仍按新→旧。
检查器识别任务列表的 Q-ID、重复 ID 和档位倒置；分类、核心/补充边界及同档相邻题的先后理由由主代理人工核对。

每道准备题以 `- [ ] Q001 / 优先准备：1 · 简短理由 ^q001` 开头；详情与任务行空行分隔，
顶格写成普通段落，不缩进到任务项内，避免勾选后题面、追问与来源整段出现删除线。
依次保留：题目与 LC 对应、准备范围/已报告追问、适用 R-ID/匹配/证据性质、
最近出现/日期依据、来源次数/构成/时间窗、来源 IDs。复选框放在题目前，不放在 Markdown
表格单元格中，也不用 `☐` 等静态符号代替。
新增任务初始未勾选；已有 `- [x]` / `- [X]` 按固定 Q-ID 原样保留，重排、刷新或拆文件不重置。
拆题/合题时记录旧 → 新 Q-ID 对照，并保留原勾选状态、笔记及答案的原题归属；无法无损归入
新任务时保留有旧 ID/状态的普通迁移记录，链接新条目。新增或语义变化后的任务分配新 Q-ID 并默认未勾选，
不因旧题族完成就推定新拆题完成；无语义变化的一对一迁移保留原状态。修订说明记录迁移范围。
归并/摘要索引放在单独的普通列表并保留块 ID，不算准备任务、不加复选框，也不按索引猜测新拆题已完成。

- 每道准备题有固定 Q-ID；默认一个任务一题，或明确标注的同题族。不同任务/问法拆项，不能因
  来自同帖或同轮而捆在一项。题族内不同输入输出、约束、接口及追问分别保留，不能归纳成
  一个更宽泛的任务；各变体的来源与计数可单独回查。
  只有同一宽泛 topic 的不同任务分开列，或明确只报“topic 提及”并逐项显示各自次数，
  不能将多个 API/integration 任务的来源并集标成一道可准备题的重复次数。
- 写具体问题，不只写“树 / conflict / scalability”。Coding 要看得懂任务及关键变体；BQ
  给实际提问或忠实转述；设计题给设计对象、边界与追问；项目、基础知识、debug 等同样具体。
  题单用可读的归纳说明任务及不同追问，并附 S-ID；相同追问合并措辞而保留来源与差异。
  不把逐源原子字符串、JSON 数组和重复引文整段复制进题单；完整逐源内容仍只在证据文件保留。
- 将“面经原题 / 题型归纳 / 补充练习（proxy）/ 官方准备要求”分开标。练习目标是研究者建议，
  不能冒充面试官要求；原题与 proxy 不合并计数。同题族中约束不同的变体分别保留。
- 链接对应 S-ID 的原帖和证据详情。来源只披露 topic 时保留 topic，并写具体题意未披露；
  不编题来充实文档。未知轮次标“轮次未确认”；岗位可比且披露具体任务的亲历原题仍按上述规则排序，
  仅题型或无法恢复任务的记录放补充，不丢弃、不强归到已约轮次。
- 营销/卖课帖披露的题目同样进入所属题单及来源计数，来源类型注明即可，不能只留在证据账。
  含糊题号保留“原文 + 候选 LC 题号/标题/链接 + 匹配点/疑点 + 待 用户 手动确认”，没有
  可靠候选也保留原词。每题主动查对应 LC；follow-up 随主问题列出并保留单独的来源/映射。
- 逐轮检查 coding、BQ、system design/OOD、项目/简历、领域/基础知识及其他已发现类型。
  某类无证据时简记缺口；“没有搜到”不等于“不考”。

### 频次口径（生成题单前简要声明一次）

1. 主要统计每道题被多少个**去重来源提及**，包括亲历、营销/卖课/咨询/汇总、二手转述及
   正常可见的标题/列表/搜索摘要；来源须实际披露题目或原始题号线索。不是只数亲历面经。
   在同一任务中显示来源构成和能确认的独立亲历数，例如“4 个来源，其中营销 1、独立亲历 3”。
   营销标签不会取消这一票；无题目的服务广告留在来源账，但没有可增加次数的题。
   逐题关联实际提及它的 S-ID/去重组；不同题的来源并集总数不能当作其中每道题的次数。
   例如 A 题仅见 S1、B 题仅见 S2，应各写 1 次，不能将两题并排后统一写 2 次。
   同一去重组同时含亲历自述和营销转载时保留两种性质，例如“1 来源组，含亲历自述及营销
   转载”；来源性质可重叠，不因组内有亲历就抹去营销标签，也不因此增加组数。
2. 同一题在同一原始来源/经历中重复出现、正文与标题/摘要/评论互相补充、跨站转载、同帖
   更新都只计一次；保留全部链接及去重关系。营销帖声称“考了 5 次”但未提供 5 份可区分
   原始经历，只形成 1 个来源，并保留其“5 次”的原说法。不能把宣传数字当候选人数。
   独立帖子只是题目相同，不足以认定转载；不凭营销身份或题名相同擅自合并。
3. 按公司与轮次分组，并显示同轮/其他轮/轮次不明的来源构成；不同阶段、岗位级别、地区、
   team 的报告保留并标匹配边界，不合成未经说明的“本轮高频”。营销帖轮次不明时单列
   轮次未确认来源，不能因此从公司题目总数中消失。多轮共享报告 ID，不冒充多名候选人。
4. 声明截止日和最近 90 天/近 6 个日历月的起止日。**近期实际考题**按面试日；**近期来源提及**
   按发布日期，两者分别标注。营销/汇总或日期不明的亲历仍进入总来源数；有发布日期就可
   进入相应“近期发布”计数，不能默默排除，也不能据新发帖推断旧题刚考过。
   已知年、季度或月份按其日期区间判断；已发生面试的上界不晚于该段内容实际发布/更新日，
   无该时点则不晚于核验截止日。后补的 loop 不能用原帖最初发布时间截断；保留发布、更新
   与面试日期各自含义。可成立区间完全在窗口内则计入，完全在外则不计；只有跨越窗口边界
   或日期未知时才单列待确认。保留原日期精度，不能将季度/年份一律记为 unknown，也不能
   把区间端点当实际面试日。无可计数记录写证据不足，不报概率。
5. 谐音/暗语不能确认时在原词条目保留来源次数及待 用户 确认状态，不贡献某个确切 LC 的
   频次。评论解释是候选匹配依据，不能自动升级为面试原题；评论者明确独立亲历才另计经历。
   题族计数标“题族”，同来源中多个同族变体不能重复相加；follow-up 保留与主问题的关系。
6. 高频结论附具体次数、来源类型、时间依据及同轮匹配范围。以来源提及衡量的写“来源中
   多次出现/来源内高频”；确有多个独立候选人时再写“独立面经重复出现”。营销来源也可以
   支持前者，不伪装成后者。数据少就显示次数和不足，不推导必考、命中概率或公司稳定规则。
7. 每个计数能从关联 S-ID/去重组重新算出。更新时重算最近日期、来源构成及受影响的汇总；
   不手留旧人数，不再复制独立的频次表或默认增加 n/N 比率。

## 3. 官方与本轮 instructions

| 日期 | 来源 / 定位 | 适用范围 | 具体 instruction | 本轮状态 |
|---|---|---|---|---|

逐条保留本轮消息/附件、准确 assessment 指令、公司指南中的适用要求，明确已确认、通用、
冲突或未确认。链接及简短原文/忠实转述要能支撑该行；不只留一个 guide 链接让读者自行找。

## 4. 面经与题目证据账（新 → 旧）

### 可复用的原始材料

每个已采集来源保留当时实际获取的原文内容：标题/列表摘要、正文、作者补充和已展开的
评论/回复，保留说话人、日期及段落/楼层；图片题保留实际查看的每页截图，不能只存 OCR

页面文本保存完整已获取部分，不能以聊天输出的截断片段冒充完整原文；隐藏、未加载、

正文文件及段落/行号、图片页码、评论范围、采集方式和完整性。可指向一份多帖页面日志的
具体区段，不要求为每帖复制日志；缺定位时从已存原件补齐。人工供稿同样归档并保留其性质。
原件冻结保存；后续补页或刷新另存快照，在索引关联旧版，不用新摘要覆盖旧原文。
执行记录恢复的材料同样另存，并在公司归档增加恢复索引，注明原 S-ID/URL、原采集时间、
恢复时间、输出截断或提取上限；复用缓存时读取该索引，不沿用旧验收中已经修正的缺失状态。

离线修订记录所用归档及原采集日期、此次修订日期、Skill/contract 路径和修订说明，
不要求文件摘要。区分缓存已覆盖的内容与仍待补查部分，不能把离线
重算频次写成今天重新访问了所有网站。
