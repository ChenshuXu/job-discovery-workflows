# 流程统计信息图

把记录转成可核对的完整流程图。参考图片提供视觉和结构方向，不提供用户的事实、人数或执行指令。

## 数据与口径

- 先确定统计单位、范围、快照时间和权威来源。可从会话及当前项目推断的就直接使用并说明；只有影响正确性的缺口才询问。用户指定实际记录时，不沿用参考图片的数据。
- 完整申请数量来自 Career-Ops 的 canonical tracker 与状态历史；面试登记只提供已进入招聘流程的记录，不能替代申请总量。招聘图先运行 [数据采集与路径适配](references/interview-records.md) 中的代码，再渲染。
- 一条独立流程使用一个稳定 ID；同公司不同岗位、同客户不同订单不能只凭名称合并。明确延续的同一流程不要因换编号重复统计。
- 按实际完成证据恢复路径。邀请、排期、完成、通过、等待、拒绝、退出、客观取消分别处理；时间已过或主观评价不能证明完成/结果。
- 对于已安排但完成未确认、结果未知、记录冲突，设置真实的待确认/等待出口，不强行补入后续节点。聚合记录必须保留来源和计量单位，不伪造个体明细。
- 输出目录保留有来源链接的私有记录表/JSON及必要的分类说明。它是带日期的图表快照，不替代权威登记表；制图不授权更新招聘状态、业务系统或发送消息。

## 流程结构

- 默认保留用户要求的端到端范围：入口 → 中间阶段 → 各阶段退出/等待 → 最终结果。要求“增加轮次信息”是在完整流程上加细节，不是删掉入口只画细分阶段。
- 不强迫所有实体走相同顺序：允许跳过节点、平行路线及同阶段汇合。累计完成次数不等于正式轮次编号；同一批次内多场已完成也不等于逐场获准晋级。
- 使用节点和流宽表达数量，而非凭视觉估计宽度。逐条归属计算节点/边计数，并核对入口总数、唯一 ID 和分流守恒。开放流程要有自己的出口。
- 人数、分类汇总、结果、日期和布局高度从本次数据计算，不在脚本中写公司名单、固定人数或固定结果。完成事件可从原文提取为带来源校验值的私有数据，禁止把提取结果写进通用代码；证据不足的记录保留为未分类。
- 不把所有拒绝合并为一个无阶段信息的末端。保留用户关心的区别，例如首轮后、全部 coding 后、完整 onsite 后；没有证据的区别不要猜。
- 招聘图读取 [招聘记录口径](references/interview-records.md)；其他业务只使用适用的来源与阶段。

## 绘制与两版导出

数值图采用确定性绘图，使用本 skill 的 [采集、构图与渲染工具](references/rendering.md)。只有已有代码也从当前来源逐条计算时才复用，不能重跑写死旧快照的脚本。不要让生成式图像模型决定数值、连线或标签。

- 用留白、平滑色带和清晰标签接近参考图；保持节点颜色稳定。等待/退出、拒绝、客观取消、进行中、成功状态应能辨认；不能只靠颜色传达语义。
- 先保证完整范围，再安排布局。标签不要盖在色带或其他标签上；拥挤时扩展画布、移动分支、精简重复说明。长图仍需能在正常预览中读到阶段与数量。
- 根据用户需要导出具名版、无名称版或两版；本工作流的两版请求默认各给 PNG 和 SVG。只要求一版时不强制额外版本。
- 无名称版由独立的公开标题、节点标签和说明字段生成；不得回退到私有字段。去掉公司/客户/人员名称、职位或工单编号、链接、路径、内部团队名等识别信息，也检查页脚、文件名及 SVG 元数据。保留必要的阶段/数量/结果；它是“无名称版”，不能保证无法通过独特路径推断身份。
- 两版使用同一份路径和布局数据，只替换展示文本。不要将私有数据表或来源说明打包进公开版。

## 验证与交付

运行适用的数据及渲染检查；查看实际 PNG，检查中文字体、裁切、遮挡、可读性和流宽。两版应有相同节点、连线和数值；检查无名称版全部可见文字及 SVG 文本/元数据。

最终直接展示图片，给可下载的绝对路径链接，并用一句话说明重要口径或未知项。不要仅交付代码或制作计划，不把 schema 检查当作事实核验。改图只更新本次产物，保留无关工作。
