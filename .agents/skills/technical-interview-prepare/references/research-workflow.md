# 联网调研与来源 worker

脚本路径均相对于本 Skill 根目录。仅在本轮需要联网采集时读取。第 2 节负责派发与交接，第 3 节负责浏览边界，第 4 节负责搜索覆盖。
离线修订不读取本文件；采集 worker 跳过模型派发设置及其他平台的专属细则。
缓存定位或原帖链接失效时，再读[入口的缓存规则](../SKILL.md#归档作为缓存)，先恢复已有材料，不重复采集。

## 2. 主代理 + 三个来源 worker

先按缓存与待查项决定派发；完整公司调研只有三路都有缺口时才启动三个来源 worker 并行采集。使用当前运行时的 sub-agent
工具（Codex 中为 `collaboration.spawn_agent`），不要创建三个用户侧独立任务。worker 按入口 Skill 的按角色读取表加载规则，覆盖所分配来源中的所有问题类型，不只找 coding。

| 负责人 | 来源与职责 | 独占交付文件 |
|---|---|---|
| 主代理 | 锁定身份与已约轮次；邀请、官方指南、JD、在线附件；统一核对 LeetCode 原题、去重、频次与最终文档 | canonical prep doc + 独立证据账 |
| Worker 1：英文网站 | Google 通用发现、Reddit、Glassdoor、Blind、LeetCode Discuss、其他论坛与个人复盘 | `worker-1.md` |
| Worker 2：小红书 | 站内搜索、图片/正文、作者补充和评论，营销/卖课内容照常纳入 | `worker-2.md` |
| Worker 3：一亩三分地 | 面经板块列表/标题预览、公开题目页、可访问正文和评论，谐音及隐藏正文的可见线索 | `worker-3.md` |

### 可配置的模型与推理强度

手动编辑 [worker-config.json](../worker-config.json) 中各 worker 的 `model` 和
`reasoning_effort`，分别对应上表的 Worker 1–3；主代理沿用当前对话设置。
这是本 Skill 的派发配置，由主代理读取，不是 Codex 自动加载的全局设置。

- 每次需要派发 worker 时，先读取配置；本轮用户明确指定的值优先，只作本轮覆盖，除非要求保存。
  启动前检查所需条目、非空字符串及当前工具支持的模型/推理组合；无效或不可用时说明具体
  配置问题，不静默继承主代理或替换模型。无需 worker 的缓存修订不受此配置影响。
- Codex 派发使用 `agent_type: "default"`、`fork_turns: "none"`，将对应值显式传入
  `collaboration.spawn_agent` 的 `model` 和 `reasoning_effort`。完整历史继承或固定模型的
  agent 类型可能覆盖配置；因此将下述任务上下文及缓存路径直接写进派发消息。
- 配置文件只保存在本 Skill 目录，不在 `context/Interview/` 下创建或复制配置文件。
  本轮覆盖只用于派发；在 worker 交付头记录 agent ID、
  请求的模型/强度及工具实际确认的设置（未返回则注明未确认），不把配置值当作实测执行证据。
  首步检查同时核对工具返回或可读执行元数据的实际模型/强度；不符则停止该 worker 并纠正
  派发，不能继续采集后再用末尾免责声明代替配置落实。无法取得元数据时明确标为未确认。
  原 worker 补查/反向核对沿用启动设置；手改文件用于后续新派发，不自动改变已运行 worker。

### 派发与协作

完整原件与日志保存在文件中，不在消息里再次全文复制。worker 交接只发新增/修正的 S-ID、
完整问题与追问条目所在位置、覆盖状态和待决问题；主代理读取相关证据条目，对关键映射、
高频、冲突及抽查异常回读原件，不例行重读全部浏览日志。采集者仍须实际读完相关原文和图片，
反向核对仍从原件逐项出发，不能用短摘要替代必需的题意、约束、追问或读取范围。

- 主代理先完成身份消歧，再向有待查项的 worker 分别派发：准确公司/职位/req、R-ID 与已约日期、
  轮次已知/未知信息、查询时间窗、来源边界、用户提供的论坛分类链接、本文件及 contract 的必读章节、缓存路径、真正待查项及独占输出文件绝对路径。
  主代理创建一个本次研究的临时目录，仅为实际派发的 worker 创建表中对应文件；告知 worker 还有其他代理
  在工作，只写自己的文件，不改 canonical 文档、tracker、记忆或其他 worker 的结果，也不再
  嵌套派生 worker。主代理在三者采集期间完成官方来源调查；新确认的轮次/题型及时通知
  原 worker 调整查询，不能始终沿用派发时的未知形式。
- 各 worker 可用 Google 的站点限定搜索发现自己负责的网站，但须遵守第 3 节用户提供一亩三分地分类链接时的入口规则。发现其他 worker 所属来源时，
  传递 URL 和已见摘要，由所属 worker 阅读详情；一亩三分地始终只有 Worker 3 导航访问，
  主代理和其他 worker 不另开其页面，不以多人各自限速叠加站点请求。
- 主代理和每个 worker 各用自己的 Ego Lite task space；主代理派发互不相同的空间名，
  worker 返回数字 ID 后持续复用。每段 heredoc 显式选择自己的 ID 和目标 tab，再观察页面；
  不共用 tab、`@N` 引用或抢占其他代理的空间。若实际出现空间/tab 状态串扰，先停止并发
  浏览，由主代理依次调度浏览操作，保留原来源负责人，不引入额外锁库或调度脚本。
- worker 自主完成第 4 节的定向查询、翻页/滚动、重要线索处理与覆盖自查，不逐批等待主代理
  审核或追加指令。达到查询终点并处理重要待查项后，一次交付本批来源成果；真实受阻时交付
  已得材料与具体缺口，按访问规则交接。采集期间仍持续落盘，不把“一次交付”理解为最后才保存。
  worker 边采集边写自己的临时文件，按 document contract 第 4 节保留来源细节。临时 S-ID 分别用
  `S-W1-001`、`S-W2-001`、`S-W3-001` 等前缀。交回已读来源、查询/翻页与停止位置、访问
  状态、图片/评论可见范围、跨站同源线索、谐音候选及所有 follow-up；不能只交题名摘要。
  主代理集中核验 LeetCode 对应，worker 可提交候选链接与匹配线索，不能把候选当作已确认。
  worker 在交付前自查字段与归属、原件可读性、正文/图片及追问完整性、日志终态和覆盖终点。
  来源记录可用 Markdown，不要求另造 JSON schema；记录完整题意及候选线索，不承担标准 LC
  核对或跨帖题目归并。主代理采集期间只处理官方材料、身份/范围澄清、访问交接及明确的
  材料质量问题；不因收到部分题意提前做 LC 核对、题目归纳或排序，不逐批审核搜索进度。
- worker 完成本批后交付实际入口、定向查询、已读/待读项、停止依据、查询时间窗、实际覆盖
  截止与遗留缺口。主代理验收一次：满足第 4 节条件或真实受阻即可收尾，不因仍有普通链接
  扩搜。漏做指定查询、原件截断/缺图，或整合发现影响题意/归属/计数的具体冲突，才定向
  退回原负责人；说明来源 ID/查询、缺少什么、补齐条件，不重新派发整个来源调研。
  超时或无消息不等于搜索完毕。补查用 `collaboration.followup_task`，保留已读 URL 与来源 ID；
  单个平台只唤醒该 worker，不重复访问受限来源，不由其他代理代开页面绕过限制。
- 本批所有实际派发来源均结束或真实受阻、已得证据归档后，固定本批材料，再由主代理统一
  核对 LC、跨帖去重、计算频次、排序和生成文档。受阻来源按部分完成记录，不等待人工验证
  阻止其他成果整合；恢复后作为补充批次合入。整合与反查发现的具体缺项仍可定向修复，
  修正后仅复核受影响条目及关联计数/引用，不把普通新链接当作重开采集的理由。
- 遇 CAPTCHA/滑块/人工登录验证，暂停当前 worker 在该 task space 的这条浏览工作线，
  保存验证页面并用 `handOffTaskSpace(id)` 交给 用户；通知主代理是哪条线、哪一页待处理。
  确认交接实际成功；主代理用原生问题输入工具说明页面、空间、人工动作和待续操作，接收
  用户 的完成/继续确认；工具不可用时用聊天询问，不以只有进度消息的方式结束交接。
  其他 worker 和不依赖该页面的工作继续，不广播全任务暂停或仅因验证码全站停用。
  同一 worker 可做已有材料的离线整理，但不再操作已交出的空间，也不让其他 worker 代开
  受阻页面绕过验证。验证页保留，不作为已完成空间关闭。
- 用户 明确说已验证、可以继续后，主代理只唤醒对应 worker；它按 Ego 的接回步骤恢复
  原空间/原 tab，先观察并保存当前状态；验证仍在则继续交接，消失后接续。页面自动变化、
  等待超时或其他 worker 完工不算确认。多条线都在等待而“继续”指向不明时，仅确认目标线。
  用户接管/inactive/unassigned 同样只暂停受影响空间的浏览线；只有 用户 要求全部停止，
  或实际控制状态影响其他空间时才扩大暂停范围。这是 用户 明确指定的本流程交接边界，
  优先于 ego-browser 中将单空间交接扩大为整个多-worker 任务暂停的默认措辞。
- 没有可处理验证页面的真实 403/429/封禁仍停止该来源并通知主代理广播共享来源停用；
  其他允许来源继续。不得自动重试、另建空间或换 worker 绕过限制。
- 只有主代理合并到 canonical 文档：按原帖/经历去重、复用既有 S-ID、保留新旧 ID 对照，
  重算全局来源次数及来源构成，不能把 worker 的计数直接相加。引用材料先归档到公司目录，
  再写文档中的逐条定位。每次交付检查点归档已完成来源批次，不等整场长任务结束才保全。
  保留采集时的原始交付与日志；后续修正另记，不为消除临时路径
  改写原始证据。读者文档中的链接和纯文本定位均指向持久副本，不能只替换文首总链接。
- 每个 worker 在主代理确认来源覆盖、证据已落盘后，按 ego-browser 的独立收尾 heredoc
  关闭自己的空间并回报实际结果；不得关闭别人的空间。后续离线核对复用原 worker，
  无需重开浏览器。主代理完成文档验证后关闭自己的官方调查空间；真实访问限制按规定交接。

若运行时没有 sub-agent 能力或不足三个并发槽位，明确说明实际情况，按相同分工分批完成；
不得声称三个 worker 已并行运行。

## 3. 所有网上访问都用 Ego Lite

- 开始浏览前读取并执行 [单步采集与落盘](capture-step.md)：一次页面动作后即保存
  原文与完整进程日志，运行 `scripts/check_capture.py` 并观察实际结果，再决定下一步。
  主代理与所有采集 worker 都使用同一入口；禁止一段脚本里连续导航多个查询/帖子/页面。
- 从当前宿主的 Skill 列表定位并完整读取已安装的 `ego-browser` 的 `SKILL.md`，用其 `ego-browser nodejs`
  heredoc、task space、页面观察和清理流程。Google 搜索、官网、论坛、Reddit、Glassdoor、
  一亩三分地、小红书、LeetCode 原题页及在线附件均在 Ego Lite 打开。
- 本工作流不使用 web search/fetch 工具、curl、Jina、Exa、RedBookSkills、OpenCLI、其他浏览器
  或平台 API；其他 skill 的默认来源路由不能覆盖用户的 Ego Lite 要求。也不以 `serverFetch`
  或 `browserFetch` 代替页面阅读。可以读取已交付的本地文件和本次页面提取结果。
- 各代理复用登录态与各自固定的 task space；通过快照/DOM 获取页面文本与链接，图片题用截图实际阅读，
  不能从标题猜图。小红书逐张检查可访问图片、正文、作者补充及相关评论/展开回复，记录
  未加载的图片/评论范围。营销、卖课、咨询或汇总帖的题目照常提取、进入题单和来源出现次数，
  标明来源类型；不能只归档在末尾或因为营销身份就不给频次计数。
- 截图从生成时就写入本次目录下含 worker、S-ID/官方来源和页码的独占路径，不依赖默认
  临时文件名。若当前截图 helper 的目的路径参数未经确认，在同一 Ego heredoc 内用
  `cdp('Page.captureScreenshot', {format: 'png'})` 返回的 `data` 解码写入独占 PNG，再查看
  该文件；截图后立即复制公共路径仍有竞争。无法独占输出时只串行截图。记录实际 URL、
  tab 与图号，并核对图内内容；错图不能单凭路径或复制成功认定已修复。
- 一亩三分地要分位置检查：面经板块列表/标题页及其预览摘要、搜索结果摘要、帖子可见正文、
  作者补充、楼下评论和展开回复。正文隐藏不等于无信息：这些正常可见位置可能披露部分题意、
  题号、样例或追问。只读当前获准访问的页面；保留每段线索的 URL、位置和说话人，明确
  “标题/列表摘要可见”“评论线索”“正文仍隐藏”，不能声称已读取隐藏全文。
- Worker 3 自动打开正常获准访问的 `/bbs/` 面经列表，先核对实际 URL、公司筛选与列表标题。
  **用户直接提供一亩三分地论坛分类链接时，以该链接为入口，在站内筛选目标公司、按日期浏览列表并读取相关帖子；
  不使用 Google 搜索一亩三分地帖子，也不为补足题型查询或覆盖验收追加 Google 搜索。**
  入口不可用或帖子受限时，按访问规则记录缺口/交接，不自动改用 Google。未提供分类链接时沿用通常的入口发现规则。
  可从 `https://www.1point3acres.com/bbs/forum.php?mod=forumdisplay&fid=145&filter=sortid&sortid=311&orderby=dateline`
  进入，再在页面选择目标公司；这个通用入口本身不证明已筛选公司。`/interview/` 题库或付费
  产品只能补充，不能代替 BBS 列表、帖子和评论，也不能用另一产品的会员墙判定 BBS 受阻。
- 一亩三分地保留低频访问约束：单 tab 串行、相邻允许导航至少间隔 10 秒、缓存已读 URL，
  不刷新重试或批量开页，不绕过积分、隐藏内容或验证码。普通获准 BBS 阅读无需另请 用户
  手动打开；实际需要人工登录/验证或控制交接时，按下条暂停等待。
- 访问限制与控制交接统一按第 2 节处理，记录 URL/可见范围。全部操作只读，不发帖、互动或购买权限。
  限制必须来自实际响应状态或可见的验证/封禁提示；DOM ref、URL、题号里出现 403/429
  不算受限。普通 selector/导航超时先观察当前页面与控制状态，再决定修正动作，不当作站点封禁。
- 受限帖子可以由 用户 人工供稿接续。主代理汇总具体帖链接、限制和缺少的正文/图片/
  评论范围，让 用户 选择完成验证后继续，或把自己可访问的内容以截图、摘录、转述提供。
  不要求重写整帖；收到材料后按 document contract 归档、提取题目和追问、核对 LC 并合入
  原报告，不必重新访问受限原页。缺原帖链接也保留材料，标来源定位/去重待确认，不强认
  为新的独立来源。人工供稿不解除站点限制；已交出控制时，等 用户 明确“继续”或要求
  整合再接续。仅要求整合供稿不授权恢复该站浏览；完成验证并确认继续后才接回原空间观察。
- 保留浏览调用的完整返回，不只取 `.output`。`exec_command` 返回 `session_id` 就通过
  `write_stdin` 等待退出；外层 `functions.exec` 返回运行中 cell 则用 `functions.wait`。
  等待期间照常沟通，终态确认前不启动同空间后续浏览、不判定预期文件缺失或任务完成。
  CLI 启动时直接把 stdout/stderr 写入独占文件，不在返回后才复制聊天输出；先保存页面文本
  再截图，失败前已返回的正文仍须保留。搜索后核对实际关键词、结果区/URL的变化，隐藏
  或 0×0 输入框、Enter 无变化都不算完成查询。切图/展开评论后等内容稳定并核对页码、
  图片内容或回复状态；固定等待秒数、点击成功和重复截图都不能单独证明读到了下一页。

## 4. 搜索与采集

先查该轮邀请、recruiter 指令、官方 candidate guide、assessment 说明、附件和准确 JD。
将本轮明确要求与公司通用指南分开；官方也不能证明某道社区报告题会在本轮出现。

使用 Google 中英文查询和可用的站内搜索，至少检查 Reddit、Glassdoor、一亩三分地、
小红书、Blind、LeetCode Discuss；保留其他论坛、个人复盘、工程博客等有效结果。
组合公司别名 + role/team/level/location + 轮次原名/同义词 + interview/面经/真题 + 时间范围。
按已约形式补充 coding、BQ/behavioral、system design、HM/project deep dive、debugging、
code review、pair programming、OOD、domain knowledge、AI-assisted coding、presentation 等查询，
不把所有技术轮都假设成 LeetCode，也不因叫 coding round 而漏记开场 BQ 或项目问题。
各 worker 在原交付内记录“已约题型 → 实际定向查询/入口 → 结果或具体限制”。本轮含 BQ、
项目或设计，就要做相应查询；泛搜碰巧读到几个 BQ，不等于已检索该题型。某个平台无站内
搜索可在允许的 Google 站点查询中补足；Google 受阻不代表其他平台可用的站内搜索也受阻。
用户提供一亩三分地分类链接的情形按第 3 节执行：记录公司筛选、列表日期范围、相关帖及各已约题型的读取结果，
作为该平台的题型覆盖检查；不要求逐题型另做搜索。列表达到下述终点且重要待查项已处理，即可结束该平台。

默认面经发现范围为核验日向前 **6 个日历月**，优先最近 90 天，记录实际起止日期；
不因材料稀疏自动扩到更早年份。面试日期已知时按面试日期判断，未知时以披露该经历的
发布日期筛选并注明；近期转载不刷新已知旧经历。日期区间跨边界或日期未知的相关线索
可检查以确定归属，仍不明就标未知，不为确定日期反复扩搜。用户明确指定范围时以其为准。
官方指令、LC 标准题核对不受面经时间窗限制；已存或偶然看到的旧材料保留为历史补充，
不因此继续展开旧帖、旧推荐或重采缓存，也不追溯删除既有题单、勾选状态和原件。
平台有可验证的时间筛选/排序就使用；只有混排时记录限制，按逐帖日期判断，
不能凭一页旧结果认定已越过窗口。可验证的倒序列表到达窗口边界后停止翻页，处理完已发现的重要线索。

### 停止搜索与进入收尾

- **重要待查项**：窗口内、与本轮形式可比且可能补充具体题目/追问、改变近期独立来源次数或
  准备排序的线索，以及会影响本轮指令、题意、去重或归属的冲突。新 URL 本身不构成补查理由；
  级别/地区未知或营销身份本身也不能作为排除理由。已见其他轮次/旧题仍保留，保存不等于继续调查。
- **每条查询的终点**：结果耗尽、可验证的时间边界，或连续两个实际加载的结果页/滚动批次
  没有新增重要线索时，停止该查询。重复截图、加载失败不计批次；同题的新独立亲历仍算新增。
  已发现的重要待查项仍须处理为已读、重复、有依据的低相关/窗口外或真实受阻，不能留着未读却报完成。
  已读后仍缺日期/题意且无具体可追线索时，保留未知即可，不将其作为无限补查项。
- **平台完成**：第 4 节要求的本轮定向查询/可用入口已检查，各查询已到终点，且没有未处理的
  重要待查项，即可结束该平台。一个查询饱和不代替其他必要查询；必要查询完成后，不为“也许还有”
  无限换词。只为具体缺口追加轮次别名或题名查询，并在原交付中写明缺口及可能影响。
- **全局收尾**：官方要求已核对，各来源达到上述完成条件或有真实阻碍后，停止新增来源发现，
  归档覆盖结果并进入固定材料的合并、LC 核对和反向审查。审查仅为新发现的具体重要缺口重开
  对应来源；原件能解决的离线修正不重开搜索，未知或低相关线索不自动重启整个平台。
- **完成与部分完成**：达到搜索终点并处理重要线索可以报告范围内完成，不承诺全网穷尽。
  访问限制按第 2 节暂停/交接受影响来源；用户规定的时间或范围边界到达时停止并记录未完成项，
  有实质缺口则标部分完成。不能仅凭已读篇数或耗时宣称覆盖充分，也不能因仍有普通链接而拒绝收尾。

在 worker 原交付和证据账的覆盖栏记录查询、窗口、最后结果页/批次及停止依据、重要待查项的
处理结果；不新增调度器或独立台账。新增阅读围绕本轮形式、题意、去重或冲突进行，
不为扩大题量继续展开无关推荐和商业通用目录。

给每个来源固定 S-ID，每段面试经历分配报告/去重组 ID。worker 边读边保存到独占临时文件，
主代理再合并到独立证据账。两者的完整字段、原始材料及逐轮归属统一遵循
[document contract 第 4 节](document-contract.md)，
来源计数遵循其中第 2 节的频次口径。
